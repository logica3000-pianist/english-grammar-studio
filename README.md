# English Grammar A2–C1: content files

`manifest.json` lists the 100 units in sequence, their prerequisites and their relative paths. All 100 unit files are available. `schema.json` is a JSON Schema 2020-12 for unit files; completed units are in `units/`. `validation-report.json` records actual checks and outstanding work. `progress.json` records the next unit and the change log. The level placements are pedagogical choices compatible with the CEFR, not an official universal grammar syllabus.

Each unit contains its ID, level, title, order, prerequisites, objectives, explanation sections, examples, common errors, summary and exercises. Every exercise has an ID, type, instruction, prompt, difficulty, tests_units and explanation. `mcq` adds four options, an answer ID and per-option feedback; `gap` adds accepted_answers; `correction` adds source_sentence, target_segment and accepted_answers; `transformation` adds source_sentence, keyword (possibly null), target_sentence, min_words, max_words and accepted_answers. The optional `grading` object explicitly overrides case sensitivity and terminal-punctuation handling for an exercise; if present both booleans are required.

For text answers, trim leading and trailing whitespace, collapse consecutive whitespace to one space, convert typographic apostrophes to straight apostrophes, compare case-insensitively by default and ignore terminal punctuation by default. Preserve internal apostrophes and words. Apply exercise-level `grading` overrides if present. Compare the normalised answer with every normalised accepted answer; do not infer additional answers. For transformations, count words in the trimmed, whitespace-collapsed response before comparison, treating space-separated tokens as words; require min_words through max_words inclusive. For corrections, present the source sentence and identify the exact target segment; compare only its replacement. For MCQs, compare the chosen option ID with `answer` and show the corresponding `option_feedback`; show `explanation` for overall feedback.

Load `manifest.json`, select an available unit and load its UTF-8 JSON from the relative `path`. Validate it against `schema.json`. For a unit score, award one point per correct exercise and calculate `100 × correct / attempted`; for a completion score, use all 24 as the denominator. Store responses, correctness and completion by stable unit and exercise IDs, never by array position. Preserve IDs when content is corrected.

Minimal example: A2-U01-E01 asks `I ___ from Brazil.` Its correct option ID is `b` (`am`); selecting `b` earns one point and displays feedback for `b`.
